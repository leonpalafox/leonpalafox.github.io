# Search discoverability audit — 18 October 2026

Two passes on the same day. The first crawled all 44 sitemap URLs and fixed
crawl signals and legacy URLs (commit `74a6588`). The second re-audited the
local build and the live site (HTTP behaviour, DNS, every outbound link,
rendering at 390 px and 1440 px), fixed what the first pass missed or broke,
and corrected two of its conclusions. No Google Search Console or Bing Webmaster
Tools access was available, so this is not an indexing report and makes no
ranking claims.

## Verdict

The pages themselves are in good shape: crawlable, canonicalised, sitemapped,
with unique metadata and valid structured data. The largest remaining problem is
outside this repository: **the bare domain `leonpalafox.com` is on GoDaddy
domain forwarding, and every deep link to it returns 404.** After that, the
constraints are editorial: the columns are republished verbatim from
El Financiero, which usually wins the headline query.

## Corrections to the first pass

- **Search Console is probably already set up.** The first pass reported no
  verification. There is a `google-site-verification` TXT record on
  `leonpalafox.com`, which indicates a Domain property that never needed an
  HTML tag. Check that property before creating a new one.
- **Apex canonicalisation only worked for the homepage.** `leonpalafox.com/`
  takes two hops (`→ leonpalafox.github.io → www`), and every other path on the
  bare domain returns 404 from the forwarder. See issue 1.
- **Share image sizes.** Covers are not 1200×800; they are generated 1200 px
  wide at their own aspect ratio (675, 800 or 1499 px tall), and the declared
  sizes match. One cover is portrait (1200×1499); platforms centre-crop it.

## Open issues, in priority order

### 1. Fix the bare domain at GoDaddy — highest impact, about 10 minutes

`leonpalafox.com` and `leonpalafox.com/<anything>` are served by GoDaddy's
forwarding service. Old links, people typing the domain without `www`, and the
Jekyll-era URLs under the bare domain all land on a 404.

In GoDaddy DNS for `leonpalafox.com`:

1. Turn off domain forwarding.
2. Replace the apex `@` A records (`3.33.251.168`, `15.197.225.128`) with
   GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`,
   `185.199.111.153`.
3. Add AAAA records: `2606:50c0:8000::153`, `2606:50c0:8001::153`,
   `2606:50c0:8002::153`, `2606:50c0:8003::153`.
4. Leave `www` (CNAME to `leonpalafox.github.io`), the MX records (GoDaddy
   mail) and the `google-site-verification` TXT record exactly as they are.

GitHub Pages then redirects the bare domain to `www` with the path preserved,
in one hop. The custom domain in the repo's Pages settings stays
`www.leonpalafox.com`. Afterwards, `curl -sI https://leonpalafox.com/blog/`
should return a 301 to `https://www.leonpalafox.com/blog/`. While in DNS
settings, consider verifying the domain with GitHub (Settings → Pages →
Verified domains) to block takeovers.

### 2. Use the Search Console property

Open the existing Domain property, submit
`https://www.leonpalafox.com/sitemap-index.xml`, and check Page indexing for
"Duplicate, Google chose different canonical" (the El Financiero copies) and
"Not found (404)" on bare-domain URLs, which should clear after issue 1.
Import the property into Bing Webmaster Tools instead of verifying separately.

### 3. Duplicate content with El Financiero — editorial

Unchanged from the first pass: the outlet publishes the same text first and has
more authority, so it takes the headline query. A short, unique author's note on
each personal copy (context, what changed since, links to related columns) is
the only way to make the copy rank on its own. Do not add a canonical to
El Financiero unless you want the archive out of search.

### 4. Legacy course sites point their canonical at github.io

`/mlclase/`, `/dsclase/` and `/dbclase/` are separate Jekyll repos (last built
around 2019). Their canonical is `https://leonpalafox.github.io/<repo>/`, which
redirects back to `www`. Add `url: "https://www.leonpalafox.com"` and
`baseurl: "/<repo>"` to each repo's `_config.yml` (any push also rebuilds them),
or archive them if the new course pages replace them.

### 5. Broken outbound links

- `etica.md` links its El Financiero original at
  `/opinion/leon-palafox/los-datos-representan-el-mundo-…`, which returns 500;
  date-pattern variants return 404. Find the current URL on the author page.
- `frameworks-deep-learning-historia.md` links PyTorch 2.0 at
  `https://docs.pytorch.org/blog/pytorch-2.0-release/` (404). The working URL is
  `https://pytorch.org/blog/pytorch-2.0-release/`. Left alone because that file
  has uncommitted edits.

The rest of the 110 outbound links resolve, or refuse automated requests only
(USA Today, Medium, Bloomberg, OECD, YouTube rate limiting).

### 6. Titles over 60 characters — optional

Three headlines run 78–80 characters and will be truncated or rewritten in
results. They are the published headlines, so this is editorial: shorten them or
accept Google's rewrite.

### 7. Thin pages and topic hubs — editorial

`/portfolio/` (42 words in the main column) and the 2018 RIIAA notes are thin.
Tag pages would mostly duplicate `/blog/`, since nearly every column is tagged
`mexico`, `financiero`, `ia`. Curated hubs with real introductions are only
worth it if you will write those introductions.

### 8. Minor

`/blog/nfl-power-rankings-week-6/` overflows by 10 px at a 390 px viewport
because of a wide data table. This predates both passes and is also live.

## Verification (second pass)

- `npm run build`: 44 pages (87 HTML files with redirects). Static audit: no
  duplicate titles or descriptions among indexable pages, every indexable page
  self-canonical and in the sitemap, no broken internal links (the only
  misses are the three legacy project sites, which are live, and relative links
  inside the unpublished PISA template).
- Structured data parses on every page; `BlogPosting` has `dateModified`;
  class-session breadcrumbs have four levels.
- `updatedDate` exercised on a scratch build and then removed: visible date,
  `article:modified_time`, `dateModified` and sitemap `lastmod` all appear.
- PISA: `assemble.py` (with its source validation), `validate_data.py` and the
  unit tests pass on a scratch copy; output is byte-identical to the published
  page. `build_data.py` was not re-run, since the data did not change.
- Chrome device emulation at 390 px and 1440 px: no horizontal overflow on the
  homepage or articles; the new previous/next block and homepage eyebrow
  render as intended.
- `git diff --check`: clean.
